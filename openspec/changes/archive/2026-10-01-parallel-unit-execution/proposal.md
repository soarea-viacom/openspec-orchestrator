# Proposal

## Why

Apply today runs every dispatch group in the change's one worktree, so workers cannot commit, cannot run a gate on their own slice, and cannot be checked before the slices are combined. Nothing makes a worker write checks before code, nothing caps its loop, nothing looks at what a UI change renders, and integration is a single orchestrator commit per wave. Units fix this: each independent slice of tasks.md gets its own branch, worktree, and worker; it writes executable checks (screenshots for UI) first, loops on them under an engine-enforced cap, gets reviewed alone, and is integrated in dependency order before the existing Check/Verify/Gate 2 path runs unchanged.

## What Changes

1. **Split into units, recorded in state.** New action `split` at `applying` with `units` empty: the generator (`deep`) writes `units "<u>=<file>,<file>;..."` (seam dialect), `unit_deps "<u>=<dep>,<dep>;..."`, `unit_tasks "<u>=<task-id>,...;..."`, `ui_units "<u>,<u>"`. New `units check` (lib.sh `units_check`, state-only, also used by `next`): acyclic deps, every dep a known unit, every unit file in the `seams` lists, overlapping file lists only between units ordered by a dep path, each task id in at most one unit; the CLI additionally prints tasks.md ids assigned to no unit. New `units single [--ui]` writes one unit `all` (union of seam files, every task id) — used by `lifecycle: light` and `parallel: false`. New state fields `units`, `unit_deps`, `unit_tasks`, `ui_units`, `parallel` in `cmd_state_init`. AUTONOMOUS-ORCHESTRATION.md Phases step 4 rewritten; CONTEXT.md **Unit** replaces **Dispatch group**.
2. **Worktree + branch per unit; one Agent per unit.** `workspace_path <slug> <name> [<unit>]` → `<store>/.orchestration/workspaces/<name>.<unit>`; new `unit_branch` → `change/<name>.<unit>`. New `unit create --unit` (no tier option — unit writers are `standard`; branch off `change/<name>` tip, refused while the change worktree is dirty, records `base`, status `running`) and `unit remove --unit`; `workspace remove` also removes the change's unit worktrees/branches; `gate run --unit` runs a gate in the unit worktree without writing `gate_tree`. New `unit_concurrency` capacity (`orchestration.unit_concurrency`, default `orchestration.concurrency`). Scheduler `units next` (ready units in `units` field order, deps merged, up to free capacity; `running`, `reviewing`, `conflict` units hold a slot); `units list`; `unit get|set --unit`; per-unit state file `<state>/<name>.units/<unit>.yaml`; `status` gains a `UNITS` column. Isolation (Git) rule: a unit worker commits on its own branch only.
3. **Check-first worker contract.** New `unit checks-done --unit` records `checks_commit` (refused when HEAD is still `base`); `unit iterate` refuses until it is set. UI units (`ui_units`): a Playwright script (target-project devDependency `playwright`, the one dependency a worker may add, listed in the unit's files and shown in the Gate 2 diffstat) writes a screenshot to the `$UNIT_SCREENSHOT` path `unit iterate` exports and asserts layout invariants. Contract text in AUTONOMOUS-ORCHESTRATION.md new section **Unit workers**.
4. **5-iteration cap, logged, engine-run checks.** New `unit iterate --unit` (`UNIT_ITER_CAP=5`): refuses a 6th call and marks the unit `failed`; otherwise runs `gate_quick` in the unit worktree itself with `UNIT_SCREENSHOT=<abs path of screenshot-<n>.png>` and `UNIT_NAME=<u>` exported (only the owning unit's UI test writes the PNG), derives green/red from the exit code (green for a UI unit also requires that PNG), records `screenshot`, appends `role worker phase unit unit <u> event iterate iteration <n> checks <r> tier standard model <m>` to the session log. The worker never asserts its own result.
5. **Critic over green units, with screenshots.** New action `unit-critique` (tier/model from `critic_pick`, one above the proposer) over `units ready-for-review` (green, no critique): prints each unit and its screenshot paths. `model critic --unit <u>` prints the unit-critic input contract (`checker_inputs unit-critic`). Report `<state>/<name>.units/<unit>.critique.md`, which must contain the unit's recorded absolute `screenshot` path verbatim for a UI unit; field `critique: clean|warnings:<m>|blocking:<n>`; new action `unit-revise` on blocking (within the cap), else `gate1`.
6. **Merger in dependency order.** New `units merge-order` (topological, ties by `units` field order, error on cycle) and `unit merge --unit` (none tier): refuses a diff outside the unit's files or an unmerged dep, rebases onto `change/<name>`, fast-forwards the change branch, ticks the unit's tasks, removes the unit worktree/branch, status `merged`. A rebase conflict aborts, prints the files, status `conflict`; new action `merge-conflict` (orchestrator sets `resolving`) dispatches one `standard` agent confined to those files; a second conflict, or a `resolving` unit whose rebase is still in progress, → `failed` → `gate1`; every `unit merge` outcome logs `event merge`. All units merged → new action `units-merged` (`set_phase: checking`) → existing full gate + Verify on the change branch → existing Archive, merge lane, Gate 2, squash-merge.
7. **next_action branches.** `accepted` → `apply` becomes tier `none`, model `-` (still `set_phase: applying`; reason: commit any uncommitted work in the change worktree, then the split follows). At `applying`: `split`, `unit-spawn`, `unit-critique`, `unit-revise`, `unit-merge`, `merge-conflict`, `wait`, `gate1`, `units-merged`; every output at `applying` other than `split` carries a `running:` line and, where it names units, a `units:` line. Header comment and "Driving the loop" action list updated.
8. **Single-worker baseline.** `parallel: false` (state field; empty reads `orchestration.parallel`, empty reads `true`) makes `split` a none-tier `units single`. Default stays parallel.
9. **Tests** in `tests/run.sh` for every command above; **docs** SKILL.md, AUTONOMOUS-ORCHESTRATION.md, CONTEXT.md, README.md; **release** via `atlas bump skill openspec-orchestrator --minor -m "..."` (releases.json never hand-edited); **demo** on chess-game: a 3-feature request run parallel and single-worker from the same trunk, wall-clock compared.

## Capabilities

### New Capabilities
- `parallel-units`: unit split, per-unit worktree/branch lifecycle, scheduler, check-first worker contract, iteration cap, unit critic, merger, single-worker baseline.

### Modified Capabilities
- `orchestration-lifecycle`: Lifecycle field (light = one none-tier unit), Checker input contract (`model critic --unit`).

## Impact

- Files: `scripts/lib.sh`, `scripts/run-change`, `tests/run.sh`, `SKILL.md`, `AUTONOMOUS-ORCHESTRATION.md`, `CONTEXT.md`, `README.md`, `releases.json` (written by `atlas bump` only).
- Behavior: `apply` is a none-tier bookkeeping step (no worker is dispatched on it); `next` at `applying` no longer returns `apply`. A pre-1.4.0 change already at `applying` gets `split`; the orchestrator first commits any uncommitted wave work in the change worktree (`unit create` refuses a dirty change worktree). Unit workers commit; all other workers still never run a git write.
- Not changed: Gate 0 (mandatory, no cap, light option); Gate 1; Gate 2 and its squash-merge; trunk preflight; `tasks open` / `tasks-open` / `gate2-manual` manual-task block; `lifecycle: light` semantics other than one unit; `merge-lane run`; `FIX_CAP`, `PROPOSE_CAP`, `ADVISOR_CAP`; fix-round tier ladder; Verify and its tier rule; `checking` and later `next_action` branches.
- Target projects: a UI unit adds `playwright` as a devDependency of the target project; the engine has no new dependency.
- Installed copy `~/.claude/skills/openspec-orchestrator/` is not written and not part of this change.
